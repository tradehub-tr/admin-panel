# Motion report B: Media Explorer and Media Library

Status: done. No build, docker or commit was run.

## Files changed
- `src/views/system/MediaExplorerView.vue` (admin explorer)
  - The loading card now appears only on the first load (`!hasLoaded`). On later folder or page changes the old content stays in place inside `.mx__region` with `aria-busy` set and `inert`. If loading takes longer than 150ms it dims to opacity .6.
  - `<Transition name="mx-swap" @leave="leaveNow">` is keyed on `shownKey` (path + page), and the key is committed only when data arrives. New content fades in over 160ms with `$ease-out`. Old content is removed at once (`leaveNow` calls `done()` synchronously, so nothing overlaps).
  - Added a `loadSeq` guard so a stale response can no longer overwrite a newer one. This matters because old content stays visible while the next load runs.
  - `loadFailed` is no longer reset when a load starts. During a retry the error card stays (dimmed) until the result arrives, so an "empty folder" never flashes in between.
  - Tree rows (`.mx__tr`) get a `background-color`/`color` transition, 150ms `ease`.
- `src/views/seller/SellerMediaExplorerView.vue` (seller explorer): same pattern (`.sx__region`, `sx-swap`). `locationKey` is built from the virtual path + page, or the real-folder stack + page. Search is deliberately left out of it. The pre-mount state keeps the empty grid, as the SSR test expects.
- `src/components/media/MediaFolderGrid.vue`: adds `mfgrid--enter` for 400ms after mount. Cards fade up 6px over 150ms with `$ease-out`; cards 2–6 are delayed 30ms each and the rest have no delay. The parents re-key the grid on each folder change, so the effect plays only then: not on re-renders, and not for cells that windowing mounts during scroll.
- `src/views/seller/MediaLibraryView.vue`: `<Transition name="mswap" @leave="leaveNow">` wraps the grid/rows/table/kanban/empty chain inside `<div :key="resultsKey">`.
  - `resultsKey` = mode + grid columns + `pageSwap`.
  - `pageSwap` increments only when `paged` arrives with a different page and the query (filters, search, sort, page size, archived) is unchanged. Typing in search or changing a filter never re-animates.
  - Enter: opacity 0→1 + translateY 4px, 150ms `$ease-out`; leave is instant.
  - No TransitionGroup or FLIP was added. The fade, dropdown and mdetail transitions are unchanged.
- Tests:
  - `src/views/system/__tests__/mediaExplorerLoad.test.js`: JSDOM now uses `pretendToBeVisual` and `requestAnimationFrame` is exposed, because Vue's `<Transition>` needs rAF.
  - New `src/views/system/__tests__/mediaExplorerMotion.test.js` (4 tests). One mounts the real admin SFC: the boot card shows only on first load; on the next folder load the old content stays with aria-busy and inert; afterwards the wrapper is replaced by a new key. The others check the transition wrappers and keys in the source, plus the folder-grid stagger and the library key (no search/filter, no TransitionGroup).

## Reduced motion
- The global `base.scss` rule cuts durations to 0.01ms.
- The library drops `translateY` under `prefers-reduced-motion`, leaving opacity only.
- The folder grid switches to an opacity-only keyframe with `animation-delay: 0` under reduced motion. Without this, the delays would have kept cards hidden.

## Verification
- ESLint and `prettier --check` pass on all 6 changed files.
- `node --test` over views/seller, views/system, components/media (+ a11y) and stores/media*: 351 tests, 350 pass. The 1 failure is `cropStudioA11y.test.js` ("uyarı kimlikleri… 10 !== 11"). It is unrelated: that test doesn't import any of these files, and the file already has uncommitted changes from someone else.

## Concerns
- Seller real-folder mode: `enterFolder` updates `folderStack` immediately, so the dimmed "old" content partly switches to the new folder's sub-folders and shows stale or empty rows until the files load. The virtual tree has no such problem.
- Seller `useMediaBrowser.load` has no stale-response guard; I didn't touch the composable. Breadcrumb clicks during a load could still race, but they could before this change too.
- Admin `specialLabel()` reads the live `path`, so while a load is in flight a few special folder labels (`__other__`) on the dimmed old grid can switch to the new context's label.
- The library wrapper re-mounts the grid/table on density or page change. Windowing re-attaches through `watch(containerRef)`, and selection lives in the store, so both are unaffected. It does cost a full card re-mount on a density click.
- Focus after a folder change still drops to body, as it did before (the content is replaced). No new focus handling was added.

# Follow-up (2026-10-01): stale responses, focus after folder change, sidebar press

Status: done. No build, docker or commit was run. No new dependencies.

## Files changed
- `src/composables/useMediaBrowser.js`
  - Added a `seq` guard to `load()`: only the latest request applies its result. Older late responses, whether success or error, are dropped, and `loading` is cleared only by the latest request.
  - New export `shownPath` is committed together with the data. `path` still updates on click, so the breadcrumb is immediate.
  - `error` is no longer reset when a load starts. It is cleared when the result commits, as in the admin `loadFailed`.
- `src/views/seller/SellerMediaExplorerView.vue`
  - Virtual tree: content uses `shownPath` instead of `path`. This covers `gridItems` (the root check that adds real root folders), `specialOf`, `folderLabel` and the `rootStats` watcher.
  - Real folders: added a `folderSeq` guard plus `shownStack`/`shownInFolders`/`shownFolder`, committed together with `folderFiles`.
    - `folderStack` (breadcrumb and toolbar actions) still updates immediately.
    - Content (`gridItems`, `showFiles`, `showGrid`, `rows`, `hasError`, `listTotal`/`listPage`/`listPageSize`) reads the committed stack. The dimmed view therefore keeps the old folder's sub-folders and files, with no new sub-folders or empty list leaking in.
    - Going back to the root crumb from real-folder mode and deleting the last folder both go through `loadFolderFiles()`. With an empty stack it commits at once and drops any request still in flight.
  - Focus: region gets `ref="region" role="region" tabindex="-1" :aria-label="hereLabel"`. The flag is set in `onSelect`, `onJump` and `onSetPage`, and consumed in the existing `[locationKey, isLoading]` watcher once loading ends (then `nextTick`).
- `src/views/system/MediaExplorerView.vue`
  - `userLoad()` sets the focus flag and is used by `enter`, `jump`, `goScope`, `setPage` and the retry button.
  - First load (`onMounted`), search and the reload after an access change do not set the flag.
  - The flag is consumed by the latest load in `finally` (success or error).
  - Region gets `ref="region" role="region" tabindex="-1" :aria-label="<last breadcrumb label>"`.
- New `src/lib/media/regionFocus.js` → `focusRegionIfLost(region)`:
  - Moves focus only if it was lost: `activeElement` is body or null, is disconnected, or is inside the old region.
  - Focus that stays on a still-mounted control (tree button, search input, a crumb still present) is left alone.
  - Uses `preventScroll: true` when the region top is on screen. When the top is off screen it lets the browser scroll so the new content is visible.
- Focus ring on both regions: `:focus-visible` → `outline: 3px solid $brand-text; outline-offset: 2px` (`$brand-light` in dark mode). `:focus` without `-visible` shows no outline, so mouse users don't get a ring box.
- `src/assets/scss/sidebar.scss`: `.panel-group-title` gets `&:not(:disabled):not([aria-disabled="true"]):active { transform: none; }`. Specificity is (0,4,0), above the global rule's (0,3,1), so no `!important` is needed and stylesheet order doesn't matter.

## Focus decision
- Card click: the card is unmounted when new content arrives (and in a browser `inert` already runs focus fixup), so focus falls to body → the region is focused.
- Tree (admin `.mx__tr`): the buttons stay mounted → focus stays.
- Breadcrumb: in `MediaCrumbs` the clicked crumb becomes the last item and turns from `<button>` into `<span aria-current>`. That button is unmounted, so focus moves to the region. A crumb that stays mounted keeps focus.
- Search and pagination: search input stays. The pagination button is inside the re-keyed region → region.

## Concerns
- `inert` focus fixup isn't modelled in JSDOM. The tests cover the "card removed → body" path, which is the same end state.
- Admin `specialLabel()` still reads the live `path`. The earlier concern (a few `__other__` labels switching on the dimmed grid during a load) remains on the admin side; only the seller side was moved to committed state.
- Seller pagination `model-value` reads the requested `folderPage`/`page`, so the clicked page highlights while the old page is dimmed. This is intentional.
- The focus flag is consumed on the next load that is not busy. A user navigation superseded by a non-user load still focuses once, and only if focus was lost.
